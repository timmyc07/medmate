# 藥品官方用法、成分與安全公告整合設計

## 目標

將 TFDA 藥證資料中的官方用法用量、詳細處方成分，以及官方藥品安全風險溝通公告接入藥品查詢頁，維持資料來源可追溯並避免推測性配對。

## 資料與關聯

- `36_2.csv` 的「用法用量」存於 `medicines.usage_dosage`，依完整許可證字號更新。
- 相同許可證的重複用法列只可在內容完全一致時折疊；同證不同內容會停止匯入並回復交易，避免隱性選取其中一種說明。匯入回報未匹配既有藥證的用法筆數。
- `43_2.csv` 為一張許可證對多筆成分，使用獨立 `medicine_ingredients` 表保存所有欄位與來源時間；完整重複列可去除，不得依成分代碼合併不同含量或處方標示。
- `53_2.csv` 以獨立 `medicine_safety_communications` 表保留公告原文及來源資訊。只有從「藥品名稱及許可證字號」欄抽出、並能在許可證表精確找到的完整字號，才以 junction table 建立藥品關聯；其他公告維持公告層級，不以成分或品名推測。
- 匯入須在單一交易完成，維護來源 URL、抓取時間、SHA-256、原始筆數與批次 UUID；缺檔、欄位或許可證參照驗證失敗時回復交易。

## 網站呈現

許可證搜尋卡提供可展開的官方用法用量、處方成分與精確關聯的 TFDA 安全公告。公告文字標示發布日與官方來源，保留原文，不轉寫成診斷或個人治療建議。來源沒有用法資料時清楚顯示「官方未提供」。網站不自行生成副作用、禁忌或交互作用資料。

## 驗證

測試 CSV 正規化、完整重複去除、同證多成分保留、公告日期、完整許可證字號抽取、無模糊配對與回傳 DTO；執行全套測試、型別檢查、lint、production build 及 diff 檢查。資料庫匯入需先在隔離 Neon branch 驗證筆數、唯一許可證、完整外鍵與來源 hash，再依部署流程更新正式環境。
